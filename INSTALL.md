# Installing Maria Padilha

Maria Padilha is a Wayland desktop built on Hyprland and Quickshell. It is early
software (`0.1.x`): back up your existing configuration before installing.

There are two profiles:

| | `--full` | `--rice` |
| --- | --- | --- |
| Shell, commands, theme engine | yes | yes |
| Hyprland config | yes | yes |
| nvim and wezterm configs | yes | no |
| Session entry (`Maria Padilha` at the greeter) | yes | no |
| systemd user units | yes | no |
| Keeps your current display manager | — | yes |

`--full` is for a machine where Maria Padilha is the desktop. `--rice` is for someone
who already runs Hyprland and only wants the shell, theme, and Hyprland config.

## Requirements

- Arch Linux or an Arch-based distribution (Manjaro is the tested one)
- A Wayland-capable GPU; Hyprland must already work on the machine
- Network access, `sudo`, and about 2 GB of free space for the build
- A display manager for `--full` (LightDM is what this checkout uses); it does
  not have to be configured by the installer
- An existing Hyprland session for `--rice`

The installer has its own runtime list in `install.sh`, kept in sync with
`packaging/PKGBUILD`; the important pieces are Hyprland, Quickshell, Qt 6,
PipeWire, `brightnessctl`, Python, Lua, ImageMagick, the session daemons
(`hypridle`, `hyprsunset`, `gnome-keyring`, `polkit-gnome`), the clipboard
tools, and fuzzel. Screenshots, recording, and the Discord theme use optional
packages listed in the PKGBUILD.

## Quick start

```sh
mkdir -p ~/Códigos
git clone https://github.com/maria-padilha-os/maria-padilha-de.git \
    ~/Códigos/maria-padilha-de
cd ~/Códigos/maria-padilha-de

./install.sh --dry-run --full   # inspect the plan first
./install.sh --full             # or --rice
```

The checkout is named `maria-padilha-de`, matching the repository under the
`maria-padilha-os` organization.

Then reboot or log out. With `--full`, choose **Maria Padilha** in the display
manager's session menu. With `--rice`, log back into your existing Hyprland
session (or run `hyprctl reload` if you only changed the config).

The installer must be run as your normal user; it uses `sudo` for the `/usr`
steps. `pacman` will ask for confirmation before installing packages.

## What the installer does

1. Installs the build and runtime packages with `pacman -S --needed`.
2. Runs `tools/build.sh`, which configures `shell/` with CMake and Ninja.
3. Installs the QML modules and shell tree under `/usr`, and the commands under
   `/usr/lib/maria-padilha/bin` with links in `/usr/bin`.
4. For `--full`, installs `/usr/share/wayland-sessions/maria-padilha.desktop` and the
   optional systemd user units.
5. Fetches the dotfiles repository as `maria-padilha-dotfiles` next to this checkout if
   it is missing, then links its configs into `~/.config` — `hypr` for both
   profiles, plus `nvim` and `wezterm` for `--full`. An existing real directory
   is moved to `~/.config/<name>.pre-padilha-<timestamp>` first. Set
   `PADILHA_DOTFILES` (the old `LILITH_DOTFILES` is still accepted during the
   transition) to use an existing checkout elsewhere.

Use `--no-dotfiles` to leave the linked config directories untouched (the
default-editor file under `~/.config/environment.d` is still written, and
`xdg-mime` is still set). `--dry-run` prints every command without running it,
including `sudo` and `pacman`.

## First login

- `Super + Return` / `Super + T` opens the terminal.
- `Super + Escape` locks; `Super + Alt + Escape` restarts the shell and locks.
- `Super + Alt + h/l` changes workspace; `Super + Alt + j/k` changes monitor.
- `Super + Ctrl + h/j/k/l` resizes the active window.
- `Super + Shift + P` shows all panels.

The full keymap is in [KEYBINDS.md](KEYBINDS.md). The wallpaper and palette are
applied by `padilha-daylight`: a light period from 06:00 and a dark period from
18:00. Change the wallpaper with:

```sh
padilha wallpaper -f ~/Pictures/wallpapers/example.jpg
```

## Configuration

| path | role |
| --- | --- |
| `~/.config/hypr` | Hyprland, keybinds, rules, execs |
| `~/.config/nvim` | the Neovim config (full profile) |
| `~/.config/wezterm` | the terminal config (full profile) |
| `~/.config/padilha/init.lua` | the shell's Lua configuration |
| `~/.config/padilha/local.lua` | machine overrides |
| `~/.config/padilha/ui.lua` | generated by the settings UI |
| `~/.config/padilha/theme.lua` | optional theme-engine switches |

`~/.config/hypr/hyprland/env.local.lua` is for local secrets and is ignored by
git. Do not commit it. See [CONFIG.md](CONFIG.md) for the configuration contract.

## Rice-only notes

`--rice` installs the shell and commands but deliberately leaves the session
entry and systemd units out. Your existing Hyprland session entry still starts
Hyprland; the `maria-padilha-dotfiles` `execs.lua` calls `padilha-session` from
`/usr/bin`.

If you keep your own Hyprland config with `--no-dotfiles`, start the shell
yourself after Hyprland is up:

```sh
padilha-session
```

To use only the Quickshell shell with your own Hyprland configuration, copy the
relevant `exec` lines from
`../maria-padilha-dotfiles/hypr/hyprland/execs.lua` rather than replacing your
config.

## Manual and package installs

Build and install the package instead of using the direct installer:

```sh
tools/release.sh
sudo pacman -U packaging/maria-padilha-0.1.1-1-x86_64.pkg.tar.zst
```

The package installs the same `/usr` tree but does not link the dotfiles or
configure the display manager. Link them with:

```sh
../maria-padilha-dotfiles/bin/padilha-dots            # hypr, nvim, wezterm, mc
../maria-padilha-dotfiles/bin/padilha-dots hypr       # only the Hyprland config
```

MC is linked file by file: only `ini`, `mc.keymap` and `mc.ext.ini` come from
`maria-padilha-dotfiles/mc`; `panels.ini`, the hotlist and the history stay local.
The caelestia skin itself is generated by `padilha-theme` from the wallpaper.

For a checkout without root, the developer flow in the README (`tools/build.sh`
plus `QML2_IMPORT_PATH`) still works.

## Updating

```sh
cd ~/Códigos/maria-padilha-de
git pull --ff-only
./install.sh --full             # or --rice
```

The installer is idempotent; existing symlinks are replaced, and real config
directories are backed up only when they are not already symlinks.

## Uninstall

The direct installer is not tracked by pacman, so remove exactly what it wrote:

```sh
sudo rm -rf /usr/lib/maria-padilha
sudo rm -f /usr/bin/padilha /usr/bin/padilha-* /usr/bin/lilith /usr/bin/lilith-*
sudo rm -f /usr/share/wayland-sessions/maria-padilha.desktop
sudo rm -f /usr/lib/systemd/user/padilha-*
```

Then replace the dotfile symlinks with your backups. The installer also linked
the static MC files (`~/.config/mc/{ini,mc.keymap,mc.ext.ini}`), micro's
`settings.json`/`bindings.json`, and Firefox's `user.js` plus chrome
stylesheets in the detected profile; restore or remove those by hand.

```sh
for name in hypr nvim wezterm; do
    if [ -L "$HOME/.config/$name" ]; then
        rm "$HOME/.config/$name"
    fi
done
# restore the newest ~/.config/<name>.pre-padilha-* if you need it
```

If you installed the package, use `sudo pacman -Rns maria-padilha` instead of the
manual `/usr` removals. Your `~/.config` backups are not touched by pacman.

## Troubleshooting

- **Hyprland starts without the shell**: check `hyprctl configerrors`, then run
  `padilha-session` from a terminal and read its output.
- **No Maria Padilha entry at the greeter**: confirm
  `/usr/share/wayland-sessions/maria-padilha.desktop` exists and that the display
  manager scans that directory.
- **Quickshell fails to start**: check
  `/run/user/$UID/quickshell/` for the instance log; the package installs the
  QML modules under `/usr/lib/qt6/qml`.
- **Brightness keys do nothing**: `brightnessctl --list` must show the panel;
  the brightness daemon starts from `execs.lua`.
- **Wrong colours after a wallpaper change**: run `padilha-daylight --once`,
  then `padilha-reload`.

## Repositories

Maria Padilha is split by dependency direction, not by folder names:

- `maria-padilha-de` (GitHub `maria-padilha-os/maria-padilha-de`) — the shell,
  session, theme engine, installer, and package;
- `maria-padilha-dotfiles` (GitHub `maria-padilha-os/maria-padilha-dotfiles`) —
  the standalone rice: Hyprland, nvim, and wezterm configs;
- `maria-padilha-os` — the archiso/Calamares image, only once the packages are stable.

`maria-padilha-de` fetches the dotfiles repository as `../maria-padilha-dotfiles` next to
itself for the `--rice` and `--full` profiles. Set `PADILHA_DOTFILES` if the
checkout lives elsewhere; the old `LILITH_DOTFILES` still works during the
transition. There are no submodules; the workspace-level `bootstrap.sh` clones the
siblings.
