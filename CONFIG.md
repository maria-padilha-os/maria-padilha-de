# Configuring Maria Padilha

One file, one language. The compositor is already configured in Lua; the
shell should not require a different language and a different mental model.

`~/.config/padilha/init.lua` returns a table. The compiler merges it over the
shell's built-in defaults and writes the JSON the shell reads. Nothing
downstream knows Lua exists.

## Files

| path | role |
| --- | --- |
| `~/.config/padilha/init.lua` | your config — the source |
| `~/.config/padilha/local.lua` | per-machine overrides, same shape, wins over `init.lua` |
| `~/.config/padilha/ui.lua` | generated by `padilha-config set`; wins over `local.lua` |
| `~/.config/padilha/shell.json` | generated — never edit by hand |
| `~/.config/padilha/theme.lua` | optional theme-engine switches |

During the transition, `~/.config/lilith` is still read as a fallback when
`~/.config/padilha` does not exist; new configs belong in the new directory.

## Environment variables

- `PADILHA_CONFIG` — the absolute path to the `padilha-config` executable,
  exported by `padilha-session` for the settings UI. Do not point it at a
  directory.
- `PADILHA_CONFIG_DIR` — the Hyprland user-config root, default
  `~/.config/padilha`. The legacy `PADILHA_CONFIG` name is still accepted for
  this purpose when it really names a directory.
- `PADILHA_DOTFILES` — an existing dotfiles checkout for `install.sh`; the old
  `LILITH_DOTFILES` is the fallback.
- `PADILHA_FIREFOX_PROFILE_DIR` — force the Firefox profile used by
  `padilha-theme` and `padilha-dots`.
- `PADILHA_BACKLIGHT_DIR` — override the sysfs backlight directory for
  `padilha-brightness` (mainly for tests).
- `PADILHA_CLIPBOARD` — the absolute path to the `padilha-clipboard` helper,
  exported by `padilha-session` for the clipboard widget.
- `PADILHA_CLIPBOARD_DIR` — override the clipboard state directory (mainly for
  tests). The default is `$XDG_STATE_HOME/padilha/clipboard`.
- `PADILHA_SCREENSHOT_DIR` — override the screenshot folder.
- `PADILHA_RECORDINGS_DIR` (or the older `PADILHA_RECORD_DIR`) — override the
  recording folder.
- `PADILHA_CAPTURE_DIR` — one root for both folders; screenshots go in
  `Screenshots/` and recordings in `Recordings/`.
- `PADILHA_CAPTURE_WORKSPACE` — the workspace name that counts as dedicated to
  capture. The default is `capture`.
- `PADILHA_CAPTURE_WARN_WORKSPACE=0` — silence the non-capture-workspace
  warning (the panel still shows the reminder).
- `PADILHA_CAPTURE_NOW` — a tests-only timestamp in `YYYYmmdd-HHMMSS` form; it
  is validated and can never contain a path separator.
- `PADILHA_RECORD_AUDIO_DEVICE` — a PipeWire/PulseAudio source name when
  recording with sound.
- `PADILHA_RECORD_ARGS` — extra `wf-recorder` arguments, split as shell words.
  The old `LILITH_RECORD_ARGS` name is still accepted.

## Theme settings

`~/.config/padilha/theme.lua` is optional and read by every `padilha-theme
apply`, including the daylight and wallpaper paths:

```lua
return {
    theme = {
        enableBtop = false,
        enableDiscord = false, -- opt-in; set true to enable
        postHook = "pkill -USR2 some-app",
    },
}
```

The switches are `enableHypr`, `enableHyprlock`, `enableFuzzel`, `enableBtop`,
`enableCava`, `enableGtk`, `enableQt`, `enableMicro`, `enableSpicetify`,
`enableDiscord`, `enableMc`, and `enableFirefox`. A missing file, or an omitted
key, uses the default: every switch is enabled except `enableDiscord`, which
is opt-in and defaults to false. `postHook` runs only with `padilha-theme apply
--hooks`.

### Discord (opt-in, unsupported)

Set `enableDiscord = true` to have `padilha-theme apply` compile
`share/templates/discord.scss` with the current palette into a standalone
`caelestia.theme.css`. If a supported client mod's config directory already
exists (Equicord, Vencord, BetterDiscord, equibop, vesktop or legcord), the
engine writes the stylesheet to its `themes/` folder. It does not install,
launch, patch or update Discord, the client mod, or any account.

The theme is only active after you install a client mod yourself and enable
the theme or paste the stylesheet into its custom-CSS panel. The manual
install, update and removal steps live with the
[dotfiles repository](https://github.com/maria-padilha-os/maria-padilha-dotfiles).
The generated file is self-contained: no imports, remote assets, fonts, images
or network code.

> Client modifications are against Discord's Terms of Service. Vencord and
> BetterDiscord both document this; bans are reported as rare or unknown in
> practice, but that is not a guarantee. If losing your account would be a
> disaster for you, do not use any client mod.

Spicetify is optional: the generated `color.ini` only does something when the
user already has Spotify and the Spicetify CLI installed. Maria Padilha does
not install or bundle either one. See [docs/app-themes.md](docs/app-themes.md)
for the generated files, the states they cover, and the per-app reload notes.

## Clipboard history

Clipboard history is opt-in and off by default. Enable the palette in
`~/.config/padilha/init.lua`:

```lua
return {
    clipboard = {
        enabled = true,
        maxEntries = 100,
        privateWindowDelay = 5,
        maxEntryBytes = 1048576,
        showIndicator = true,
        denyClasses = padilha.array {},
        denyTitles = padilha.array {},
    },
}
```

History is stored under `~/.local/state/padilha/clipboard` (or
`$XDG_STATE_HOME/padilha/clipboard`) and is trimmed to `maxEntries`. Nothing is
recorded while the history is paused, while a password-manager window or
password/title fragment is focused, or when the clipboard advertises a
password-manager MIME type. `privateWindowDelay` is the number of seconds to
wait after leaving a private window or password manager before recording again.
`denyClasses` and `denyTitles` extend the built-in deny lists; both are
case-insensitive substring matches.

The palette is opened by the `clipboard` shell shortcut or
`qs ipc call clipboard toggle`. It supports search, arrow-key selection,
Enter to copy back, Delete to remove an entry, the pause/resume action, and a
two-step Clear all. The same store is available without the shell:

```sh
padilha-clipboard --list          # id and preview, newest first
padilha-clipboard --copy ID       # put an entry back on the clipboard
padilha-clipboard --pause         # stop recording, keep the history
padilha-clipboard --clear         # delete every entry
padilha-clipboard --search        # fuzzel picker over the local history
```

The original `cliphist`/fuzzel picker remains the default when
`padilha-clipboard` is run with no arguments. The daemon needs `wl-paste` from
`wl-clipboard`; `padilha-clipboard --search` needs `fuzzel` and `wl-copy`, and
the legacy picker also needs `cliphist`. If one is missing the command says so
and exits with status 3 instead of failing silently.

## Screenshots and recording

Screenshots use `grim`; recordings use `wf-recorder`. Both save locally with a
timestamp and neither uploads anything. The panel in the utilities drawer is
the normal interface: choose **full screen**, **focused window** or **region**
for a screenshot, or one of the recording modes, then press **Start**. A
countdown can be configured; **Cancel** stops it, and **Stop** ends a recording.
While a recording is running, the panel shows **REC** and the bar shows a
pulsing red dot.

Settings live under `utilities.capture`:

```lua
return {
    utilities = {
        capture = {
            screenshotDir = "~/Pictures/Screenshots",
            recordingDir = "~/Videos/Recordings",
            workspace = "capture",
            countdown = 3,
            copyScreenshot = false,
        },
    },
}
```

Copies are opt-in twice over: `copyScreenshot` only sets the panel's default
toggle, and the command copies only when `--copy` is passed. Open the panel
from its shortcut or with `qs ipc call capture open`; the IPC can also take an
explicit screenshot or start/stop a recording:

```sh
padilha-shot --mode full              # save, do not copy
padilha-shot --mode window --copy     # save and copy this one
padilha-shot --mode region --countdown 3
padilha-record start --mode full      # explicit start
padilha-record status                 # idle, recording or paused
padilha-record stop                   # explicit stop
qs ipc call capture screenshot window
qs ipc call capture record region
qs ipc call capture stop
```

`--dry-run` prints the exact `grim`/`wf-recorder` command without capturing, and
the missing-tool errors name the package to install. Recordings are never
started by opening the panel; `padilha-record` with no action keeps the old
toggle behaviour only for existing keybinds.

Capture on an empty, dedicated workspace. The command warns when the active
Hyprland workspace is not named like the configured `workspace` (or
`capture*`, `screenshot*`, `record*`); `--strict-workspace` turns that warning
into a refusal. The panel never hides a browser, terminal or private window for
you, so check the workspace before pressing Start.

## Weather

Weather is explicit and never guesses the location from your IP address. Set a
city or a coordinate pair in Settings → Language & region, or in `init.lua`:

```lua
return {
    services = {
        weatherLocation = "Porto Alegre, Brazil",
        weatherCoordinates = "-30.0346,-51.2177", -- filled by the location search
        weatherUnits = "Auto", -- Auto, Celsius, Fahrenheit or Kelvin
        weatherLanguage = "", -- empty follows the shell locale
        weatherRefreshInterval = 1800, -- seconds, clamped to 5 minutes..6 hours
        weatherCacheTtl = 3600, -- seconds, clamped to 5 minutes..1 day
    },
}
```

The location search is user-triggered: typing a city and submitting the field
is the only time the geocoding endpoint is called. Selecting a result saves
both a visible place label and its coordinates. Clearing the saved location
stops the refresh timer. If you only set `weatherLocation`, the shell resolves
it once and keeps the coordinates in its response cache.

Provider URL, geocoding URL and the optional API key belong in
`~/.config/padilha/weather.conf` (honours `XDG_CONFIG_HOME`), outside this
checkout:

```ini
# ~/.config/padilha/weather.conf
provider_url = https://api.open-meteo.com/v1/forecast
api_key = YOUR_KEY
geocoding_url = https://geocoding-api.open-meteo.com/v1/search
language = pt-BR
refresh_interval = 1800
cache_ttl = 3600
```

Keep the file private with `chmod 600 ~/.config/padilha/weather.conf`. The shell
never writes it, the key is never put in the response cache, and cache keys use
the provider origin rather than its query string. The environment variables
`PADILHA_WEATHER_PROVIDER_URL`, `PADILHA_WEATHER_API_KEY`,
`PADILHA_WEATHER_GEOCODING_URL` and `PADILHA_WEATHER_LANGUAGE` win over the file;
the file wins over the Lua settings. Deployment credentials must never be
committed to this repository.

Responses are cached at `$XDG_CACHE_HOME/caelestia/weather.json` (normally
`~/.cache/caelestia/weather.json`) with the update timestamp. Fresh cache is
shown without a request until `weatherCacheTtl`; older cache stays visible as
**last saved weather** and the weather panel shows the last update time. A
failed request, a rejected key, an invalid URL and an unreadable response each
produce a clear message; the last saved weather is kept instead of being
replaced by an empty panel. There is one refresh timer in the weather service
and no per-widget polling, so the minimum interval of five minutes is a hard
floor rather than a suggestion.

## Precedence

```
shell defaults (C++)  <  init.lua  <  local.lua  <  ui.lua
```

`local.lua` is for what differs per machine (a laptop with a different bar
height, a desktop with no battery). It is gitignored, the same pattern as
`hypr/hyprland/env.local.lua`.

`ui.lua` is generated: edit `init.lua` or `local.lua` for hand-written
overrides.

## Generated settings

`padilha-config set KEY VALUE` writes a value into `ui.lua`; `unset` removes
it and prunes the empty parents. Values are parsed as JSON when possible
(`false`, `42`, `"Wallpaper"`, `[]`), otherwise they are taken as strings.

```sh
bin/padilha-config set appearance.transparency.enabled false
bin/padilha-config set bar.palette '"Fixed"'
bin/padilha-config set general.idle.timeouts '[]'
bin/padilha-config unset appearance.transparency.enabled
```

The next step is for the settings UI to call these instead of writing
`shell.json`; until then the UI's own writes are still carried over as
described below.

## What you can write

Data only:

- booleans, numbers, strings, tables
- `padilha.array {}` when you need an empty **list** — Lua cannot tell an
  empty list from an empty map, and the schema can
- anything Lua can compute: a loop that builds per-monitor entries, a table
  built from another table, `if` on hostname

Keys are checked against the shell's own schema — the `caelestia-config.qmltypes`
that `qmltyperegistrar` writes next to the module. An unknown key is an error
with a suggestion (`config.appearanc: unknown key (did you mean "appearance"?)`)
and so is a wrong type. Enum values are checked too, case-insensitively, the way
the shell reads them: `config.bar.palette: expected one of Wallpaper, Fixed,
got "Fixd" (did you mean "Fixed"?)`. `--no-schema` skips the check;
`--schema PATH` points at a different qmltypes.

## What you cannot write yet

- **Functions.** `hooks` is reserved and rejected with an error until the
  theme engine exists to call them. This is deliberate: a config that can
  hang is a config that breaks the session.
- **Reactivity.** The file is evaluated once, at compile time. It is a
  config, not a plugin: changing a value takes a compile and a shell reload,
  not a live patch.

## What the settings app changes

The shell's settings UI still writes `shell.json` directly. The compiler would
otherwise overwrite those edits at the next login, so it carries them over:

```
defaults  <  init.lua  <  local.lua  <  ui.lua  <  changes made in the UI
```

How it knows what "changed in the UI" means: next to `shell.json` the compiler
keeps `shell.json.base`, the tree the Lua sources produced last time. Anything
that differs between the baseline and the file on disk is an edit, and an edit
wins over the Lua sources — including a key the UI added that `init.lua` never
mentions. A key you *remove* from `init.lua` still disappears, unless the UI
also edited it.

`--no-merge` turns this off and writes `init.lua`'s tree verbatim; it is what
you want when the two have drifted and you would rather start from the file
you can read.

## When it is wrong

The compiler refuses to write a broken config:

- syntax and runtime errors carry the line: `init.lua:12: unexpected symbol near '='`
- type errors carry the key path: `config.bar.onClick: is a function`
- the output is written to a temporary file and renamed, so a failure leaves
  the previous `shell.json` exactly as it was
- exit codes: `0` ok, `1` config error, `2` usage

`tests/run.sh` holds those promises to the fire.

## Commands

```sh
bin/padilha-config compile                  # init.lua -> shell.json
bin/padilha-config compile --check          # parse and validate, write nothing
bin/padilha-config compile --print          # to stdout, for diffing
bin/padilha-config compile --config X.lua --out Y.json
bin/padilha-config compile --schema path/to.qmltypes   # validate against another schema
bin/padilha-config compile --no-schema                 # skip key/type validation
bin/padilha-config compile --no-merge                  # ignore UI edits, init.lua wins
bin/padilha-config set KEY VALUE                        # write ui.lua
bin/padilha-config unset KEY                            # remove from ui.lua
```

At login the session calls `bin/padilha-session`, which compiles `init.lua`
and then starts the shell. A failed compile keeps the previous JSON (the
write is atomic) and the session still comes up, with a notification. To apply
a change without logging out:

```sh
bin/padilha-config compile && padilha-reload
```

Watching `init.lua` and reloading on save comes later; `settings.watchFiles`
is deliberately off.

## Example

```lua
-- ~/.config/padilha/init.lua
return {
    appearance = {
        transparency = {
            enabled = false, -- opaque bar and drawers
        },
    },

    general = {
        idle = {
            timeouts = padilha.array {}, -- no automatic lock/suspend on idle
        },
    },
}
```

`examples/init.lua` is this file, and it compiles to exactly the `shell.json`
the machine runs today — the model is lossless before it is mandatory.
